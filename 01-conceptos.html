Conceptos clave de Docker

Las piezas y cómo se conectan: imagen, contenedor, puertos, redes y volúmenes. Si entendés estos diagramas, los comandos se explican solos.

El flujo general

De una receta (o de Docker Hub) a un proceso corriendo.

archivo de definición imagen contenedor atajo
2

Glosario rápido

Una línea para cada concepto.

Imagen

Imagen

Plantilla inmutable con SO base + dependencias + tu código. Se identifica como nombre:tag.

  • node:18, mongo:latest, miapp:1
  • Sin tag ⇒ se asume :latest
Contenedor

Contenedor

Una instancia en ejecución de una imagen. Tiene su propio sistema de archivos, red y procesos.

  • Se referencia por ID (alcanzan los primeros caracteres) o por nombre
  • Si lo borrás, se pierde lo que no esté en un volumen
Archivo

Dockerfile

Receta paso a paso para construir una imagen propia (FROM, COPY, RUN, CMD…).

  • Se usa con docker build
Archivo

docker-compose.yml

Define varios contenedores juntos: cómo se construyen, puertos, variables, volúmenes y redes.

  • Se usa con docker compose up / down
Red

Network

Permite que los contenedores se vean entre sí usando su nombre como hostname.

  • Compose crea una red automáticamente para todos sus servicios
Volumen

Volume

Almacenamiento que sobrevive al contenedor. Ideal para datos de bases de datos.

  • Nombrado: mongo-data:/data/db
  • Bind mount: .:/home/app (carpeta de tu PC)
Puerto

Mapeo de puertos

Expone un puerto del contenedor en tu PC: -p HOST:CONTENEDOR.

  • -p 8080:3000 ⇒ abrís localhost:8080, la app escucha en 3000
Registro

Registry / Docker Hub

Servidor donde viven las imágenes. docker pull baja de ahí; docker push sube.

Build

Build context

La carpeta que le pasás a docker build (el . final). COPY solo puede leer archivos dentro de esa carpeta.

3

Ciclo de vida de un contenedor

Qué comando lo lleva de un estado a otro.

!

Ojo: docker stop detiene el contenedor (envía SIGTERM, el proceso termina). Para pausar de verdad existe docker pause. Un contenedor detenido sigue existiendo hasta que hacés docker rm.

4

Mapeo de puertos

-p HOST:CONTENEDOR — siempre primero tu PC, después el contenedor.

i

-p 8080:3000 ⇒ entrás por localhost:8080 y llega al 3000 del contenedor.

i

EXPOSE 3000 en el Dockerfile es solo informativo: no publica nada. Quien publica es -p o ports:.

!

Entre contenedores de la misma red no hace falta mapear puertos: se hablan directo por el puerto interno.

5

Redes: cómo se habla la app con la base de datos

En una misma red, el nombre del contenedor/servicio funciona como hostname.

6

Volúmenes: persistir y compartir archivos

Dos sabores con la misma sintaxis ORIGEN:DESTINO-EN-CONTENEDOR.

Volumen nombrado

Docker lo gestiona. Sobrevive a docker rm y a docker compose down.

Bind mount (carpeta de tu PC)

Tu carpeta se “ve” dentro del contenedor. Ideal para desarrollo: editás y el cambio está al instante.

¿Dónde guarda los datos cada base de datos?

La ruta de destino del volumen tiene que ser exactamente esta, si no los datos se pierden al recrear el contenedor.

7

¿Qué va en el Dockerfile y qué en el compose?

Están separados a propósito.

Dockerfile

Cómo se construye UNA imagen

  • Imagen base (FROM)
  • Copiar código, instalar dependencias, compilar
  • Qué comando arranca la app (CMD / ENTRYPOINT)
  • Es reusable solo: docker build -t miapp .
  • No sabe de puertos externos, variables de entorno ni de otros contenedores
docker-compose.yml

Cómo se orquestan VARIOS contenedores

  • Qué servicios hay (app, db, migrator, frontend…)
  • build (context + dockerfile) o image
  • ports, environment, volumes, depends_on
  • La red común para que se hablen por nombre
  • Todo se levanta con docker compose up
