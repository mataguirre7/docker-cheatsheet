Cheatsheet 02

Comandos de la CLI

Todo lo que se escribe en la terminal, agrupado por tema. Los valores en <rosa> se reemplazan; las -flags en amarillo. Pasá el mouse por un bloque para copiarlo.

1

Imágenes

Descargar, listar, construir y borrar.

Descargar (pull)

docker pull <imagen>:<version>
Baja una imagen desde Docker Hub. Sin versión ⇒ :latest.
docker pull node:18
docker pull node:latest
docker pull mysql:latest
docker pull mongo
Ejemplos de tus notas.

Listar imágenes

docker images
Lista las imágenes descargadas/construidas (igual que docker image ls).
docker image inspect <imagen>
Detalle completo en JSON: capas, variables, comando por defecto, puertos expuestos.
docker history <imagen>
Muestra las capas y qué instrucción del Dockerfile generó cada una.

Borrar imágenes

docker image rm <imagen>:<version>
Borra una imagen. Atajo equivalente: docker rmi.
docker image rm node:16
docker image rm mysql:latest
Ejemplos. Falla si hay un contenedor (aunque esté detenido) usándola.
docker image prune
Borra imágenes “colgadas” (<none>) que quedan tras rebuilds. Con -a borra todas las que no usa ningún contenedor.

Construir una imagen (build)

docker build -t <nombre>:<tag> <ruta-contexto>
Construye usando el Dockerfile de la carpeta. Ojo al espacio antes de la ruta.
docker build -t miapp:1 .
El . es el build context: la carpeta actual.
docker build -t miapp:dev -f Dockerfile.dev .
Usar otro Dockerfile con -f.
docker build --no-cache -t miapp:1 .
Reconstruye todo sin usar la caché de capas.

Etiquetar y subir

docker tag miapp:1 <usuario>/miapp:1
Le da otro nombre a la imagen (para subirla a tu cuenta).
docker login
docker push <usuario>/miapp:1
Sube la imagen a Docker Hub.
2

Contenedores

Crear, arrancar, detener, listar, borrar. Se referencian por ID (alcanzan los primeros caracteres) o nombre.

Crear (sin arrancar)

docker create <imagen>
Crea el contenedor y devuelve su ID. Queda en estado created. Igual a docker container create.
docker create --name <nombre> <imagen>
Con nombre propio (si no, Docker inventa uno tipo jolly_turing).
docker create --name monguito \
  -p 27017:27017 \
  -e MONGO_INITDB_ROOT_USERNAME=mati \
  -e MONGO_INITDB_ROOT_PASSWORD=<password> \
  mongo
Con puertos (-p HOST:CONT) y variables de entorno (-e). Las flags van antes de la imagen.

Arrancar / detener

docker start <id|nombre>
Inicia un contenedor creado o detenido.
docker stop <id|nombre>
Detiene el contenedor (no lo borra).
docker restart <id|nombre>
Stop + start.
docker pause <id|nombre>
docker unpause <id|nombre>
Pausa real: congela los procesos sin detenerlos.

Listar contenedores

docker ps
Solo los que están corriendo.
docker ps -a
Todos: activos e inactivos (created, exited…).
docker ps -q
Solo los IDs (útil para combinar con otros comandos).

Borrar contenedores

docker rm <id|nombre>
Borra un contenedor detenido. Ej: docker rm 2d77ac5398a8
docker rm -f <id|nombre>
Lo detiene y lo borra en un paso.
docker container prune
Borra todos los contenedores detenidos.
3

docker run — todo en uno

1) si no está la imagen, la descarga · 2) crea el contenedor · 3) lo inicia.

Formas de usar run

docker run <imagen>
Queda “pegado” a la terminal. Ctrl+C corta la ejecución.
docker run -d <imagen>
Detached: corre en segundo plano y te devuelve la terminal.
docker run --name <nombre> -p <host>:<cont> -d <imagen>
La forma más habitual: con nombre, puerto y en segundo plano.
✕

docker run mongo -d no funciona como esperás: todo lo que va después de la imagen se pasa como argumento al proceso del contenedor. Escribí docker run -d mongo.

Recetas con run

docker run -d --name monguito -p 27017:27017 \
  -e MONGO_INITDB_ROOT_USERNAME=mati \
  -e MONGO_INITDB_ROOT_PASSWORD=<password> \
  -v mongo-data:/data/db \
  mongo
Mongo listo para usar, con datos persistentes.
docker run --rm -it node:18 bash
Shell temporal dentro de una imagen; se borra al salir (--rm).
docker run -d --name chanchito -p 3000:3000 --network mired miapp:1
Tu app conectada a una red existente.
docker run -d --env-file .env -p 3000:3000 miapp:1
Variables de entorno desde un archivo.

5

Logs e inspección

Ver qué está pasando adentro.

Logs

docker logs <id|nombre>
Lo que la app imprimió por consola (console.log, errores…).
docker logs -f <id|nombre>
Modo watch: se queda escuchando nuevos logs (= --follow).
docker logs --tail 100 -f <nombre>
Solo las últimas 100 líneas y sigue escuchando.

Inspeccionar

docker inspect <id|nombre>
Todo en JSON: IP, red, volúmenes montados, variables, estado.
docker port <nombre>
Qué puertos tiene publicados.
docker stats
Uso de CPU / RAM en vivo de cada contenedor.
docker top <nombre>
Procesos que corren dentro.
6

Entrar al contenedor y copiar archivos

Para curiosear, depurar o ejecutar algo puntual.

Abrir una terminal adentro

docker exec -it <nombre> sh
Shell dentro del contenedor (debe estar corriendo). Salís con exit.
docker exec -it <nombre> bash
Si la imagen tiene bash (las alpine no, usá sh).
docker exec -it monguito mongosh -u mati -p <password>
Consola de Mongo directo en el contenedor.

Ejecutar un comando suelto

docker exec <nombre> ls /home/app
Corre el comando y vuelve.
docker cp <nombre>:/ruta/archivo.txt ./archivo.txt
docker cp ./config.json <nombre>:/home/app/config.json
Copiar archivos contenedor ⇄ PC.
7

Redes

Para que dos contenedores se comuniquen deben estar en la misma red.

Gestionar redes

docker network ls
Listar redes (también vale docker network list).
docker network create <nombre>
Crear una red. Ej: docker network create mired
docker network rm <nombre>
Eliminar una red (sin contenedores conectados).
docker network inspect <nombre>
Ver qué contenedores hay conectados y sus IPs.

Conectar contenedores

docker create --name monguito \
  -p 27017:27017 --network mired \
  -e MONGO_INITDB_ROOT_USERNAME=mati \
  -e MONGO_INITDB_ROOT_PASSWORD=<password> \
  mongo
Crear el contenedor ya dentro de la red.
docker network connect mired <nombre>
docker network disconnect mired <nombre>
Conectar/desconectar un contenedor que ya existe.
i

Dentro de la red, la app se conecta usando el nombre del contenedor como host: mongodb://mati:<pass>@monguito:27017/miapp?authSource=admin

8

Volúmenes

Datos que sobreviven aunque borres el contenedor.

Gestionar volúmenes

docker volume ls
Listar volúmenes. Los de compose se llaman <carpeta>_<volumen> (ej: pruebas-docker_mongo-data).
docker volume create <nombre>
Crear (con -v o compose se crea solo si no existe).
docker volume inspect <nombre>
Dónde está físicamente y quién lo creó.
docker volume rm <nombre>
Borra los datos para siempre. No se puede si un contenedor lo usa.

Montar volúmenes

docker run -d -v mongo-data:/data/db mongo
Volumen nombrado: nombre:ruta-en-contenedor.
# PowerShell
docker run -d -v ${PWD}:/home/app -p 3000:3000 miapp:dev
# Git Bash / Linux / macOS
docker run -d -v "$(pwd)":/home/app -p 3000:3000 miapp:dev
Bind mount: tu carpeta actual dentro del contenedor.
9

Limpieza y espacio en disco

Docker acumula basura rápido. Leé qué borra cada uno antes de ejecutarlo.

Liberar espacio

docker system df
Cuánto ocupan imágenes, contenedores, volúmenes y caché.
docker system prune
Borra contenedores detenidos, redes sin uso, imágenes colgadas y caché de build. No toca volúmenes.
docker system prune -a --volumes
Nuclear: además todas las imágenes sin uso y los volúmenes sin uso (¡datos de DB!).
docker builder prune
Solo la caché de builds.

Borrado en lote

# PowerShell / Bash
docker stop $(docker ps -q)
Detener todos los contenedores que están corriendo.
docker rm $(docker ps -aq)
Borrar todos los contenedores (detenidos).
docker volume prune
Borra volúmenes que no usa ningún contenedor.

Ejemplo completo a mano (sin compose)

Lo mismo que hace tu docker-compose.yml, paso a paso.

App Node (chanchito) + MongoDB (monguito)

# 1. Red compartida
docker network create mired

# 2. Base de datos dentro de la red
docker create --name monguito -p 27017:27017 --network mired \
  -e MONGO_INITDB_ROOT_USERNAME=mati \
  -e MONGO_INITDB_ROOT_PASSWORD=<password> \
  -v mongo-data:/data/db \
  mongo

# 3. Imagen de la app (desde la carpeta del proyecto)
docker build -t miapp:1 .

# 4. Contenedor de la app en la misma red
docker create --name chanchito -p 3000:3000 --network mired miapp:1

# 5. Arrancar ambos
docker start monguito
docker start chanchito

# 6. Probar
#    http://localhost:3000/crear   -> crea un documento
#    http://localhost:3000         -> lista los documentos
docker logs -f chanchito
Con compose todo esto se reduce a docker compose up → ver la cheatsheet de Compose.
